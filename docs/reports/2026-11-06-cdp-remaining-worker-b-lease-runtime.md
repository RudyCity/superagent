# CDP Remaining Worker B — durable Core lease runtime (2026-11-06)

## Scope and safety
One shared checkout, `main`. No branch/worktree, commit/push, Core/Tray/MCP restart, browser/tab operation, tunnel action, secrets write, production journal write, or PID signals. Only Worker B-owned files changed. New tests operate exclusively in `mkdtempSync` fixtures.

**Live activation: BLOCKED / NOT ATTEMPTED.** In the actual runtime, `getDelegateLeaseRuntimeStatus()` defaults to `DISABLED`, and `activateDelegateLeaseRuntime()` returns `BLOCKED` without a verified in-process supervisor owner, a 128-bit unique epoch, a private-directory attestation and a stable external HMAC key. An invalid opt-in preflight also blocks the in-memory coordinator rather than falling back silently. The current Core supervisor/status and unified service ownership observations disagree and a running build is stale; none of those observations proves exclusive ownership.

## Implementation
- `delegateLeaseRuntime.ts` (new): opt-in bootstrap with a process-persistent exclusive owner file, atomic bootstrap gate, unique epoch replay prevention, explicit recovery after independently verified retirement, and an operation file kept after unknown completion. Rotated owner files retain epoch history to prevent old epoch reuse. No environment-key fallback, no auto initialization, no silent takeover of locks or journals. It accepts a protected 32-byte+ key directly from a vetted lifecycle caller. It never reads/writes a live key.
- `sessionCoordinator.ts`: optional supervisor fence verified on every durable coordinator operation; process-wide operation lock spans the asynchronous browser operation. `AsyncLocalStorage` prevents direct mutating CDP RPC bypass, counts child RPCs, and leaves unresolved-operation evidence when detached work is still pending. A valid previous epoch is only eligible for explicit recovery; corruption, lost fencing and sequence mismatches remain terminal.
- `delegateLeaseJournal.ts`: a recovered owner token may not replay `recover_session` in the same Core epoch. Existing HMAC/CAS, exact profile/tab matching and separate-epoch retirement remain intact.
- `cdpTransport.ts`: `recover_session` now calls real `recoverDelegateTarget`, requires explicit exact profile/tab + owner capability and never probes/attaches the debugger before verification. Coordinator and transport status include `durableLeaseRuntime`. The low-level attach/detach/command/tab-action RPCs must occur in the fenced operation context.
- `delegateLeaseLifecycleIntegration.test.ts` (new): fake epochs and private temporary dirs cover missing/failed proof, dual Core, bootstrap lock collision, stale owner, missing/partial/bad-MAC journal, retired-writer recovery, wrong tab/profile/token, token replay, repeated epoch, expired token, direct RPC bypass, timeout/orphan operation barriers. No live Core/Chrome calls.

## Required integration — owned outside Worker B
Do **not** wire this API from a loosely inferred `serviceManager` status or an incoming HTTP/MCP request. In a separately reviewed lifecycle-owned module (likely `src/core/runtime/coreSupervisor.ts` plus its generation/worker bootstrap), create an internal trusted `verifiedCoreOwner` only when:
1. OS port/listener, signed/current supervisor generation, worker PID/creation identity and lifecycle ledger agree. Reconcile the observed `coreSupervisor` vs `manage_services` ownership contradiction first. A PID alone or an unverified JSON discovery file must never grant ownership.
2. `assertCurrent()` is a synchronous and *continuously valid* epoch fence and loses validity on supervisor handover, not merely a one-time startup check. Retained old workers must be prevented from further browser RPCs before any successor takeover.
3. `isEpochRetired(previousEpoch)` is true only after independently verifying the previous worker is fenced and **all** accepted/in-flight browser writes are quiesced. If a pending operation marker remains, deny activation even if the process is gone; reconcile outside this module without replaying the action.
4. `assertPrivateStorage(directory)` checks canonical owner-only storage ACLs (particularly on Windows); the stable HMAC integrity key is injected from the protected lifecycle secret store. Neither key nor ownership evidence is sourced from `process.env`, UI, MCP args or journal content.
5. Invoke `activateDelegateLeaseRuntime({ directory, integrityKey, verifiedCoreOwner, initializeEmptyJournal: false })` once **before** accepting Delegate-CDP write traffic, and only after no legacy coordinator claim/in-flight target exists. `initializeEmptyJournal: true` is reserved for an explicitly approved first-time, empty installation. If return status is not `ACTIVE`, do not continue protected Core traffic.
6. A graceful fully quiesced shutdown may call `retireDelegateLeaseRuntime()` after the browser operation barrier clears. Never unlink/overwrite a stale lock automatically during recovery. The status endpoint owner (Worker C) may expose `getDelegateLeaseRuntimeStatus()` as **read only**; must not accept client-provided attestation or enable flags.

`src/core/runtime/runtimeOwnershipContract.ts` explicitly labels its observed evidence as read-only inventory and disallows process control, so it is insufficient to mint the capability. `coreSupervisor.ts` retains worker generations; the lifecycle owner must account for those before producing a signed/verified retirement proof. As this API is **not** wired into the running Core and no trustworthy lifecycle attestation has been established here, deployment remains NO-GO by default.

The separate Bun-native MCP principal suite must run with `bun test`, not Vitest. Cross-service Delegate bridge mutation paths must also be audited by their respective file owners before live enablement.
