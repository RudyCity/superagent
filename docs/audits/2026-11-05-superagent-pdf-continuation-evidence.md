# SuperAgent PDF — implementation continuation evidence (2026-11-05)

**Decision: PARTIAL / NOT PRODUCTION DONE.** This file records observed test evidence and risks. It is not independent certification, and it does not authorize changing the live MCP process.

## Completed work verified in this execution

1. **Fail-closed vector redaction safety upgrade and bounded TJ support.** `scripts/pdf_vector_backend.py` rejects scoped exact-vector redaction when the PDF contains an incremental revision marker `/Prev`, nonempty Names/XMP/associated files, document actions, optional content or tagged structure, page XMP metadata, or the selected secret in `/Info` document metadata. The operator now supports **one** unique ASCII Standard-14 `Tj` **or** simple fragmented `TJ` array (every numeric kerning adjustment within ±100; target line independently mapped), not arbitrary paragraph reflow or full-object sanitization. The change reduces false "verified" outcomes; it is not all-PDF redaction certification.
2. **New negative tests** in `tests/pdfVector.test.ts` create PDFs that hold the same visible sensitive text in metadata and an embedded attachment. The engine fails closed with `metadata_target` and `unsupported_sensitive_container`, respectively, and produces no output.
3. **Constrained positive-path regression** continues to pass for native exact text replacement, removal and independent PDF extraction plus authenticated primary MCP dispatch. No source PDF was overwritten.
4. **Pretrained OCR implemented in source** with exactly pinned RapidOCR 3.9.2 / ONNX Runtime 1.23.2 and local PP-OCRv6 Tiny/Small/Medium detector+recognizer pairs and official Tesseract eng/ind language packs. SHA-256 lock: `scripts/pdf-ocr-v6-lock.json`. No OCR training/fine-tuning. These are installed in a private user profile, not packaged for other devices yet.
5. **OCR capability**: `pdf_ocr` reads native digital text without claiming an OCR pass; scanned pages use real offline pretrained inference and return model hashes, pixel quadrilaterals, and explicit provenance. `pdf_ocr_searchable` (12th PDF tool; WRITE class) adds hidden text to a new image-only PDF while verifying independent extracted text and visible pixel parity; it is NOT privacy redaction nor original-text replacement. Tests operate on synthetic PDF scans.
6. **Four-way OCR benchmark**: `docs/audits/2026-11-04-pretrained-ocr-fourway-synthetic.json` and `.md`. All candidates evaluated on identical 12 synthetic PDF scans: Tiny CER/WER 0/0, Small 0.15%/2.08%, Medium 33.33%/33.33%, Tesseract 3.12%/8.14%. On 2026-11-05 a new **external sampled peak process-tree RSS benchmark** was run on the same 12 fixtures, saved as `docs/audits/2026-11-05-pretrained-ocr-fourway-ospeak-synthetic.json` and `.md`. It samples worker + child-process RSS at ~10ms: Tiny 360.31 MiB, Small 486.93 MiB, Medium 867.03 MiB, Tesseract 103.19 MiB on the current laptop. This is NOT a kernel high-water mark or 4vCPU/8GiB capacity certification. **No independent 200-page real-ID/EN human-gold corpus or bbox-quality reference exists.** Medium failed four noisy/small-font fixtures; none is certified production default.
7. **Digital signatures**: CMS integrity verification tested; optional OpenSSL chain validation uses only `SUPERAGENT_PDF_CA_BUNDLE`, an operator-configured trust anchor. Verified classification for trusted/untrusted/test tampered cases. Revocation (OCSP/CRL), TSA/PAdES validation, qualified identity status remain NOT CHECKED.
8. **T-Line**: PDF panel includes OCR read and searchable-copy actions, model/language selection and optional trusted-chain signature validation; it hands off to the existing Assistant with tool discovery and no direct file mutation. Installed native Tauri E2E remains untested.

The font is SIL OFL 1.1; source and license pinned in `scripts/pdf-ocr-v6-lock.json`. The font binary is not committed or distributed. `src/core/pdf/pdfSearchable.ts` checks exact font hash/size and supported glyphs, embeds only when Standard-14 encoding is insufficient, and verifies **every** OCR line in extracted output. An adversarial `TJ` adjustment of `5000` is explicitly refused without publishing output. Both remain single unique text-show cases and are **not** broader multi-run/Type0 support.

11. **Independent process-tree resource profiling (2026-11-05):** `scripts/bench_pdf_ocr_v6.py` now starts each pretrained OCR engine in an isolated worker and externally polls peak RSS for that worker **and subprocess descendants** at ~10ms via psutil. It distinguishes worker end-of-page RSS from externally sampled peak. All four candidates ran on the same 12 PDF-rendered synthetic inputs; `docs/audits/2026-11-05-pretrained-ocr-fourway-ospeak-synthetic.json` has per-engine p50/p95, input/model hashes, RSS sample counts and monitoring versions. This is **not kernel peak**, nor a benchmark on 4vCPU/8GB and 16GB devices.
12. **Latest code integrity (2026-11-05):** Unicode glyph verifier now uses the same already SHA-verified in-memory font face through a document-owned WeakMap for all OCR lines; it never reloads an unverified mutable file to approve new characters. OCR font extraction, Unicode refusal, TJ positive/negative tests and authenticated source MCP tests are all included in the 125-test run.

13. **2026-11-05 additional PDF form and preview security:** `pdf_edit` AcroForm values now use strict type-matched validation (text, boolean checkbox, enumerated radio/dropdown/options), reject read-only/XFA/signature forms, and independently reopen unflattened saved fields to check actual values. A mismatched or missing preview cannot publish. This preserves redaction's image-only fallback semantics and does not certify unselected sensitive information as erased. `pdf_ocr_searchable` now fails closed when OCR is incomplete, truncates, has invalid geometries, missing line boxes, or any omitted line instead of silently skipping bad boxes.
